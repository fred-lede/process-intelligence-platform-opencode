## 2. 產品定位

建立一套可解釋、可追溯、可切換模型的製程分析平台，協助工程師處理車載 ECU SMT、PressFit Pin X,Y,Z shift、偏位、缺件、錫珠、空洞、少錫、FATP 氣密測試等製程問題。

平台結合：

1. 傳統 DOE／田口方法。
2. AI 輔助的資料探索與模型建立。
3. DOE＋AI 的混合模型。
4. 少量驗證實驗。
5. 蒙地卡羅異常情境與超規風險模擬。
6. 可解釋 AI 助手與自動化報告。

核心原則：

> AI 可以透過多項 input、output 與時間序列資料，找出即時關聯、延遲效應、趨勢、漂移與交互作用，建立候選製程模型；少量驗證實驗用來確認其工程因果性；蒙地卡羅用來推估多變數變異、異常幅度、同時發生機率與 output 超規機率。AI 的目標是降低 DOE 實驗量與分析成本，而不是完全取代 DOE。

時間序列模型首先代表關聯與預測能力，不直接等同於因果關係。系統必須保留時間、機台、線別、批次、材料與程式版本等上下文，並可建立 lag、rolling statistics、變化量、漂移與連續超標次數等時間特徵。對 AI 發現的延遲效應、交互作用與異常模式，必須透過少量、針對性的驗證實驗確認後，才可標示為工程上已確認的關係。

## 3. 成功標準

第一版至少能完整走通一個製程案例：

```text
Excel／CSV
→ 欄位辨識
→ 資料品質檢查
→ 分布與異常偵測
→ DOE／AI／混合模型
→ 交互作用分析
→ 異常情境模擬
→ Output 分布與 NG 機率
→ Input 互動調整
→ 可追溯報告
```

系統必須能回答：

- 哪些 input 最重要？
- 哪些 input 存在交互作用？
- 一個或多個控制參數超標時，output 如何變化？
- 超標幅度有變異時，output 的分布為何？
- 多個異常同時發生的機率是多少？
- output 超規機率是多少？
- 模型可信度與限制為何？
- 下一個最值得做的驗證實驗是什麼？
- AI 與傳統 DOE 結果差異過大時，如何檢查並切回 DOE？

## 9. 資料模型與資料匯入

### 9.1 原始資料概念

第一版預設以「單片產品／單一測試樣本」作為主要分析粒度。每一列通常代表一片產品、一次測試或一個製程結果；若資料以批次或固定時間窗口提供，使用者必須在匯入設定中明確指定粒度與聚合規則。

跨製程分析透過 Barcode、序號、Panel ID、Board ID、批次、工單或使用者指定的關聯鍵串接。系統必須保留原始粒度、關聯鍵、資料對齊狀態與無法匹配的資料筆數，不得在背景中默默捨棄無法串接的資料。

支援的資料粒度包括：

- 單片產品／單一 Barcode。
- 單一製程站的一次量測。
- 單一元件或焊點。
- 單一批次。
- 固定時間窗口，例如每 5 分鐘。
- 使用者自訂粒度。

分析模型預設優先使用單片產品／單一測試樣本；批次或時間窗口資料必須在模型與報告中標示其聚合方式。

欄位類型：

- 識別欄位：日期、時間、批次、機台、線別、工單、料號。
- 製程 input：溫度、壓力、速度、孔徑等。
- output：焊點高度、空洞率、洩漏量、保持力等。
- 品質結果：OK／NG、缺陷類型、失效模式。
- 輔助欄位：操作者、材料批次、程式版本、環境溫度。

### 9.2 內部標準欄位結構

每個欄位至少保存：

## 10. 資料品質與分布偵測

### 10.1 品質檢查

必須檢查：

- 缺失值比例。
- 重複資料。
- 無效格式。
- 單位混用。
- 常數欄位。
- 極端離群值。
- 時間順序異常。
- 批次不平衡。
- OK／NG 比例失衡。
- input 超出工程合理範圍。
- output 規格缺失。

離群值分類為：

- 可能量測錯誤。
- 可能製程異常。
- 真實極端事件。
- 尚未判定。

### 10.2 分布支援

第一版支援：

- Normal。
- Lognormal。
- Uniform。
- Triangular。
- Weibull。
- Gamma。
- Beta。
- Poisson。
- Negative Binomial。
- Empirical distribution。

### 10.3 分布選擇

對連續或計數欄位執行：

```text
資料清理
→ 直方圖與密度估計
→ 偏態／峰度檢查
→ 多個分布配適
→ AIC／BIC 比較
→ KS 或 Anderson–Darling 檢查
→ Q-Q plot
→ 交叉驗證
→ 顯示推薦與信心
```

若資料多峰、批次差異大或配適不穩定，系統應推薦：

- 先分群。
- 使用批次／機台條件化分布。
- 使用經驗分布。
- 補充資料或驗證實驗。

## 11A. 資料資產管理、索引與存放結構

使用者可在專案中指定一個或多個資料來源目錄。系統掃描目錄後註冊資料集，不直接把所有原始資料送給 AI。原始資料預設唯讀；第一版支援 `.xlsx`、`.xls` 與 CSV，後續可擴充 Parquet 與資料庫連線。

```text
<project-root>/
├─ source_data/              # 原始輸入，唯讀；子目錄由使用者命名
│  ├─ <process-group-1>/     # 例如 SMT、PressFit 或其他製程
│  ├─ <process-group-2>/
│  └─ <process-group-n>/
├─ registry/                 # 資料集、欄位與來源註冊
├─ curated_data/             # 標準化資料，不改動原始檔
├─ analysis_data/            # 分布、時間特徵、模型資料集
├─ models/                   # DOE、AI、Hybrid 不可變版本
├─ simulations/              # 蒙地卡羅設定與結果
├─ experiments/              # 驗證實驗計畫與結果
├─ reports/                  # 草稿與核准報告
├─ audit/                    # 稽核與雲端傳輸紀錄
└─ project_manifest.json     # 專案設定與版本索引
```

製程資料目錄不得綁定車載 ECU 或任何特定產業。使用者可在「系統設定」或「專案設定」中建立、命名、重新命名與映射資料目錄；系統只提供 SMT、PressFit、FATP 等範例模板，不將其視為固定選項。

製程模型必須支援任意製程節點與排列組合。例如 Barcode 鐳雕、MPM、SPI、SMT 高速機、SMT 泛用機、回銲爐、AOI、X-Ray、ICT、韌體燒錄、PressFit、Pin AOI、AVI 可以形成不同的流程順序、分支或重工路徑。這些名稱只能作為使用者建立的製程節點範例，不得成為固定的程式列舉。

專案應以可配置的製程流程圖表示：

```text
製程節點 A → 製程節點 B → 製程節點 C
                    ├→ 檢查失敗 → 重工節點
                    └→ 檢查通過 → 下一站
```

每個製程節點至少保存：

```text

sequence_or_edges

output_data_sources

machine_mapping
```

同一份資料可依製程節點、產品、版本、線別、機台或批次進行分段分析；跨節點分析則透過共同的 barcode、序號、批次、工單或使用者指定的關聯鍵串接。


資料接入流程：

```text

→ 掃描檔案與格式
→ 建立資料集註冊資訊
→ 建立欄位、時間、批次與機台索引
→ 產生資料品質與統計摘要
→ 建立可分析資料集
→ AI 依需求查詢相關資料
```

資料集至少保存 `dataset_id`、來源路徑、來源檔案、格式、筆數、時間範圍、分區鍵、schema 版本、checksum、品質狀態、敏感欄位狀態與雲端傳輸政策。欄位至少保存原始名稱、標準名稱、角色、資料型態、單位、缺失率、唯一值數量、分布參數、時間語意與敏感等級。

系統至少建立檔案、欄位、時間、批次、機台、統計、品質、關聯、模型與模擬索引。向量索引只用於工程文件、報告、備註與文字規則；數值製程資料必須保留可精確查詢的表格或分析資料庫。

AI 助手先把使用者問題轉換成可檢查的分析需求，再由分析引擎執行聚合、分布、時間特徵與模型計算。AI 預設只取得欄位定義、資料摘要、分布、趨勢、聚合結果、必要樣本與模型結果，不直接讀取完整大型資料集。

大型時間序列資料應依製程、日期、機台、線別或批次分區，並支援 lag、rolling statistics、變化量、漂移與連續超標次數等特徵。轉換格式時必須保存來源檔案、轉換規則、checksum 與資料版本。

送往雲端 AI 前，系統必須顯示資料集、筆數、即將傳送欄位、已遮罩欄位與未傳送欄位，並要求使用者確認。雲端傳輸紀錄保存操作者、時間、Provider、模型版本、資料集版本、欄位、遮罩規則與使用目的。除非使用者明確確認，不得將整個資料目錄或完整原始資料集送往雲端。

## 12. 模型中心

### 12.1 模式

#### 傳統 DOE

支援：

- Full Factorial。
- Fractional Factorial。
- Central Composite Design。
- Box-Behnken。
- D-optimal。
- Taguchi Orthogonal Array。

用途：因果確認、工程報告、正式製程導入與模型回退。

#### AI 模型

第一版候選：

- 線性／二次回歸。
- Logistic Regression。
- Random Forest。
- XGBoost 或同級梯度提升模型。
- Symbolic Regression，僅作候選方程式產生器。

#### 混合模型

預設優先採用可解釋的混合模式：

\[
Y=f_{DOE}(X)+r_{AI}(X)
\]

DOE 方程式描述主要效應、平方項與已確認交互作用；AI 模型描述剩餘的非線性或殘差結構。

### 12.2 方程式建構

連續 output 的基本形式：

\[
Y=\beta_0+\sum_i\beta_iX_i+\sum_i\beta_{ii}X_i^2+\sum_{i<j}\beta_{ij}X_iX_j+\varepsilon
\]

二元 output 使用 Logistic Regression；計數 output 使用 Poisson 或 Negative Binomial；可靠度與壽命資料使用 Weibull 或相關模型。

系統需顯示：

- 方程式。
- 係數。
- 單位。
- coded／actual value 對照。
- 信賴區間。
- p-value。
- 保留／排除項目與理由。
- 適用範圍。

### 12.3 交互作用

交互作用來源：

- DOE 交互作用項。
- AI SHAP interaction values。
- 二維 Partial Dependence 或 ALE。
- 工程師輸入的工程規則。

每個交互作用必須標示：

- 已確認。
- 模型推測。
- 工程假設。
- 待驗證。

保留 (X_iX_j) 時應遵守階層原則，通常也保留 (X_i) 與 (X_j) 主效應。

### 12.4 模型比較

DOE、AI 與混合模型使用相同的資料切分與驗證條件，至少比較：

- RMSE。
- MAE。
- R²／Adjusted R²。
- 分類準確率。
- NG Recall。
- 預測區間覆蓋率。
- 殘差品質。
- 外插風險。
- 可解釋性。
- 驗證實驗結果。

不能只用單一準確度指標決定正式模型。

### 12.5 模型狀態

```text
草稿 → 待驗證 → 已驗證 → 已核准 → 已停用
```

所有模型採不可變版本，不覆蓋既有結果。

## 13. 驗證實驗

AI 不直接取消 DOE，而是推薦最少量、高資訊價值的驗證實驗：

- 模型預測最好與最差的條件。
- output 接近規格邊界的條件。
- 模型不確定度最高的條件。
- 多個異常同時發生的條件。
- 強交互作用的條件。
- AI 與 DOE 預測差異最大的條件。

每組實驗保存：

```text
experiment_id
planned_inputs
actual_inputs
predicted_output
actual_output
prediction_error
result
operator
timestamp
notes
```

驗證實驗結果可觸發模型更新，但更新必須建立新版本。

## 14. 蒙地卡羅異常風險引擎

### 14.1 模擬目的

模擬以下問題：

- 正常 input 變異造成的 output 分布。
- 一個控制參數超標時的 output 影響。
- 多個參數同時超標時的交互作用。
- 超標幅度有變異時的風險。
- 異常同時發生的聯合機率。
- output 超規與 NG 機率。

### 14.2 情境

1. 正常基準：所有 input 使用正常分布。
2. 指定異常：使用者指定一個或多個異常。
3. 自然發生風險：依異常發生率與聯合機率抽樣。

### 14.3 每次模擬

```text
產生正常 input
→ 決定異常是否發生
→ 抽取異常幅度
→ 套用聯合機率與相關性
→ 計算交互作用項
→ 執行 DOE／AI／混合模型
→ 計算 output
→ 判斷規格與 NG
→ 記錄異常組合與結果
```

### 14.4 機率與相關性

若異常獨立，可使用：

\[
P(A\cap B)=P(A)P(B)
\]

若異常有共同原因，必須支援：

- 直接指定聯合機率。
- 相關矩陣。
- Copula 或其他聯合分布方法。
- 機台／批次條件化發生率。

不能默認所有異常彼此獨立。

### 14.5 輸出

- 平均值、中位數與標準差。
- P1、P5、P50、P95、P99。
- Output 直方圖與密度曲線。
- CDF 累積機率圖。
- 正常／單一異常／多重異常箱型圖。
- 超規率與 NG 機率。
- 異常組合風險排名。
- 風險瀑布圖。
- 交互作用熱圖。
- 異常幅度與 output 趨勢圖。
- 模型外插警告。
- 模擬設定與隨機種子。

NG 機率：

\[
P(NG)=\frac{NG\ 模擬次數}{總模擬次數}
\]

## 16. AI 助手

### 16.1 能力

- 解釋目前頁面與圖表。
- 說明分布推薦理由。
- 解釋方程式、係數與交互作用。
- 找出主要風險因素。
- 建議模型與驗證實驗。
- 產生異常情境草稿。
- 摘要分析結果。
- 產生多語言報告文字。

### 16.2 權限邊界

AI 可以提出建議，但以下操作必須使用者確認：

- 刪除或排除資料。
- 修改 input／output 角色。
- 修改規格。
- 修改分布參數。
- 修改異常發生率。
- 修改模型。
- 執行新模擬。
- 將資料送到雲端。
- 將報告標記為正式版。

操作流程：

```text
AI 建議 → 預覽變更 → 使用者確認 → 執行 → 寫入紀錄
```

### 16.3 回答依據

每個重要結論顯示：

- 資料來源。
- 模型版本。
- 統計依據。
- 驗證實驗。
- 分析範圍。
- 是否外插。
- 是否仍需驗證。

AI 必須區分：

- 觀測結果。
- 模型推估。
- 工程假設。
- 尚未驗證。

## 23. 驗證與品質門檻

### 23.1 資料層

- 匯入後資料筆數與來源檔案一致。
- 欄位辨識結果可人工覆寫。
- 所有排除資料均有理由與紀錄。
- 分布圖與統計摘要可重現。

### 23.2 模型層

- 訓練、驗證資料切分可重現。
- 方程式係數與單位一致。
- 交互作用可在圖表中驗證。
- 不允許未標示的外插結果進入正式報告。

### 23.3 模擬層

- 固定隨機種子可重現結果。
- 異常發生率與聯合機率有明確來源。
- 正常與異常情境可獨立重跑。
- 模擬結果可追溯至模型與設定版本。

### 23.4 報告層

- 報告數值與分析畫面一致。
- 報告標示模型狀態與驗證狀態。
- AI 摘要不可把工程假設寫成已證實結論。
- 語言切換不改變分析數值。

## 24. 主要風險與對策

| 風險 | 對策 |
|---|---|
| 歷史資料沒有因果關係 | 以 AI 作探索，保留少量驗證實驗 |
| 量測系統不可靠 | 保留 GRR／量測品質檢查，不讓 AI 自動掩蓋 |
| AI 過度配適 | 交叉驗證、殘差檢查、模型版本與外部驗證 |
| 分布選錯 | 同時顯示經驗分布、配適指標與 Q-Q plot |
| 忽略交互作用 | DOE 項目、SHAP interaction、熱圖與工程規則並行 |
| 異常被錯當成常態波動 | 異常情境獨立建模並標示資料來源 |
| 假設異常彼此獨立 | 支援聯合機率、相關矩陣與 Copula |
| 雲端資料外洩 | 去識別化、上傳前確認、禁止欄位與稽核紀錄 |
| 使用者過度相信 AI | 顯示證據、適用範圍、外插警告與驗證狀態 |
| 報告產生錯誤結論 | AI 只能草擬；正式報告需人工審核 |

## 25. 實作交付原則

1. 先完成一個完整、可重現的製程案例，再擴充其他製程模板。
2. 所有模型、分布、模擬與報告均使用版本化資料。
3. 不把 AI 判斷隱藏在不可檢查的流程中。
4. 每個自動建議都要提供理由、來源與可接受／修改／拒絕操作。
5. 傳統 DOE 永遠保留為可執行模式、比較基準與回退方案。
6. 不以單一準確度或單一 AI 信心分數決定模型是否可用。
7. 任何正式結論都必須標示觀測、推估、假設與驗證狀態。
