# v0.5.0 受控 AI 助手規格書

**版本**: v0.5.0

**日期**: 2026-09-08

**狀態**: Draft for implementation

## 1. 目標

v0.5.0 為既有的可信分析鏈加入受控 AI 助手。助手協助解釋目前專案的分析結果、指出下一步，並建立待確認的操作草案；它不得自行確認 Gate、覆寫工程結論或直接執行會改變專案的操作。

## 2. 使用者可見能力

右側 AI 助手面板保留為全域入口。各功能頁可將目前頁面上下文帶入對話。

MVP 僅提供以下能力：

1. **解釋**：解釋目前資料、模型、外插警告、Gate 與證據來源。
2. **導引**：依專案狀態提出下一步，例如確認資料版本或建立驗證實驗。
3. **草案**：建立分析、驗證實驗或報告操作的草案；使用者確認前不得執行。

每個結論必須顯示引用的專案證據 ID 與證據狀態。沒有可追溯依據的內容必須標示為 AI 推測或未驗證。

## 3. 提供者與資料邊界

### 3.1 本機優先

預設提供者是本機 Ollama。若本機模型未就緒，面板顯示未就緒狀態與設定引導；不得自動改用雲端模型，也不得產生假回應。

雲端模型只能在使用者於設定中明確啟用後使用。

### 3.2 最小上下文

助手只能取得目前開啟專案的最小必要上下文：目前頁面狀態、資料集摘要、所選模型、Gate、版本鏈與證據標籤。它不得自動讀取或傳送完整原始資料。

### 3.3 去敏與雲端傳送

雲端模式必須先經過去敏層。預設遮罩人名、帳號、Email、電話、IP、絕對路徑、客戶或供應商名稱、料號、設備、線別與站點名稱等識別或企業識別資訊。

數值欄位預設保留原值；使用者可在預覽中改為區間化或標準化。傳送前必須顯示去敏後內容與規則清單，並允許逐欄覆寫。

每一專案首次傳送至雲端前，使用者須確認一次專案層級的傳送授權；授權可在設定中撤銷。去敏規則與授權紀錄應寫入專案的可追溯資料，但不得另存未去敏敏感值副本。

## 4. 架構

新增引擎端 **Assistant Orchestrator** 作為唯一可呼叫模型提供者與建立操作草案的入口。

| 元件 | 責任 |
| --- | --- |
| Context Builder | 依頁面與專案選取最小必要上下文與證據 ID。 |
| Sanitizer | 套用專案去敏規則，產生傳送預覽與規則清單。 |
| Provider Router | 選擇本機 Ollama，或在明確啟用與授權後選擇雲端提供者。 |
| Assistant Orchestrator | 組合上下文、執行提供者、驗證回應結構、建立草案。 |
| Action Draft | 描述既有 API 的操作、參數、影響範圍與預期結果；不直接執行。 |

資料流：

```text
目前頁面與專案
  → Context Builder
  → Sanitizer 與傳送預覽
  → Provider Router
  → Assistant Orchestrator
  → 回答、證據、建議或操作草案
  → 使用者確認
  → 既有引擎 API
  → 版本鏈與稽核紀錄
```

## 5. 回應與確認契約

助手回應必須具備：

- `explanation`：給使用者的說明。
- `evidence_ids`：引用的版本鏈或證據 ID。
- `evidence_status`：已確認、統計支持、工程假設、未驗證或 AI 推測。
- `recommendations`：下一步建議。
- `action_draft`：可選；包含操作名稱、參數、影響範圍與預期結果。
- `limitations`：資料不足、模型限制或不確定性。

前端以回答與證據來源卡、去敏／雲端傳送預覽確認卡、操作草案確認卡呈現。取消任何確認都不得改變專案。使用者確認草案後，前端才呼叫既有引擎 API；該 API 的既有版本鏈與稽核機制仍是唯一寫入路徑。

## 6. 錯誤處理

- 本機模型未就緒：顯示設定引導，不切換雲端。
- 雲端未啟用、尚未取得專案同意或去敏失敗：阻擋傳送並說明修正方式。
- 上下文或證據不足：回覆可用範圍並標示未驗證，不補造結論。
- 草案參數無效或既有 API 拒絕：顯示引擎回傳原因，專案狀態保持不變。

## 7. 驗收與測試

### 自動化測試

- Context Builder 僅選取必要上下文，且只限目前專案。
- Sanitizer 正確遮罩識別／企業識別資訊，並保留預設數值原值。
- 雲端未啟用、未同意或未確認預覽時不會接收專案內容。
- 操作草案取消後不寫入；確認後才透過既有 API 建立版本鏈與稽核紀錄。
- Ollama 與雲端 provider mock 都需驗證結構化回應與資料邊界。

### 手動驗收

1. 用本機模型解釋一次模型結果，確認可見證據 ID 與狀態。
2. 啟用雲端模式，檢閱去敏預覽與遮罩規則，再確認一次專案層級授權。
3. 分別取消與確認一個操作草案，確認只有後者改變專案且可重新開啟追溯。
4. 在 macOS、Windows、Linux 至少各確認一次本機模型未就緒畫面。

## 8. 不納入範圍

- 自動確認 Gate 或自行執行寫入操作。
- 無人值守分析與自動決策。
- 多代理協作、長期自治記憶或通用代理框架。
- 自動上傳完整原始資料。
- 即時 MES 串接與影像深度學習。
